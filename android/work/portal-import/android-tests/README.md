# 内部 Android 导入流程验证

这里的测试 APK 使用 Android 平台自带 Instrumentation，无第三方测试框架。它与正式 APK 使用现有相同签名，因此可测试非 debuggable 的正式包；私钥和密码文件不复制到测试目录，也不输出内容。

`build.py` 只生成 `build/suike-import-instrumentation.apk`。`run.py --apk <正式APK路径> --expected-sha256 <该构建SHA256>` 在安装前核对正式包版本/哈希、隔离 ADB 5041 的设备列表、工作区 AVD 名、模拟器 hardware 与 API36。测试 APK 自身也拒绝真机。

测试通过 `startActivitySync` 启动自己的目标应用，反射获取本地 WebView，再在主线程使用 `evaluateJavascript` 驱动实际导入 UI、勾选一项教室更新、取消、确认、编辑、调课和删除按钮。测试数据为 20 个课程公开字段，不使用学校账号或用户浏览器登录态。

备份验证会暂时用测试桥截获真实导出按钮生成的 JSON，检查原生备份校验与模型校验、序列化回写及 Activity 重启；此步骤不覆盖系统文件保存对话框。

学校入口验证由实际按钮打开 PortalActivity 后，在自己的模拟器 WebView 中阻止网络请求，用测试请求拦截器返回只有课程字段的表格 fixture，并通过 `loadUrl` 加载。随后点击正式代码中的原生“读取课表”按钮，实际执行固定 DOM 采集器、原生校验、内部暂存传递与本地预览，并确认尚未点击确认时存储不变。外部页面还检查没有 `SuikeNative`/`SuikeImport` 桥、文件和 content 访问被禁用。此步骤不验证学校真实登录或服务器可达性；真实个人课表 DOM 已在用户手工登录的浏览器页独立读取核对。

另有首次升级前已删除夜课的回归：模拟没有导入账本的旧数据，删除原有夜课后首次导入，仍为 177 次课程、13 次补充实验，原夜课的四次课保持删除。该测试验证旧数据兼容性，未在三星真机执行版本覆盖安装。

最终删除自己的模拟器本地课表记录，重启确认恢复默认 181 次课和无导入账本，再结束 Activity。内部报告只保留计数、布尔验证结果和构建哈希，不打印完整备份或登录信息。测试源码、测试包和报告均不进入正式交付 outputs。
